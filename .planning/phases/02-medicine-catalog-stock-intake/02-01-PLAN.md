    ---

    **`repository/medicine_repo.rs`** — All queries use `?` prepared-statement placeholders:
    - `insert(db, medicine: &CreateMedicineDto) -> Result<i64>` — returns new row id. SQL: INSERT INTO medicines (...) VALUES (...) RETURNING id
    - `find_by_id(db, id: i64) -> Result<Option<Medicine>>` — SELECT * WHERE id = ? AND is_active = 1
    - `find_all(db) -> Result<Vec<Medicine>>` — SELECT * ORDER BY name ASC, limit 200
    - `search(db, pattern: &str) -> Result<Vec<Medicine>>` — SELECT * FROM medicines WHERE is_active = 1 AND (name LIKE ?1 OR generic_name LIKE ?1 OR brand_name LIKE ?1 OR category LIKE ?1) ORDER BY name ASC LIMIT 50. Pattern already has `%` wrapped.
    - `update(db, id: i64, dto: &UpdateMedicineDto) -> Result<()>` — Dynamic UPDATE building only non-None fields. Use COALESCE pattern or conditional SQL. At minimum: UPDATE medicines SET name=?1, ... WHERE id=?2
    - `deactivate(db, id: i64) -> Result<()>` — UPDATE medicines SET is_active = 0 WHERE id = ?
    - Reactivate not needed for v1 (would be a separate feature if needed).

    **`repository/supplier_repo.rs`**:
    - `insert(db, dto: &CreateSupplierDto) -> Result<i64>` — INSERT RETURNING id
    - `find_by_id(db, id: i64) -> Result<Option<Supplier>>`
    - `find_all(db) -> Result<Vec<Supplier>>` — ORDER BY company_name ASC, limit 100
    - `search(db, pattern: &str) -> Result<Vec<Supplier>>` — WHERE is_active = 1 AND (company_name LIKE ?1 OR phone LIKE ?1) ORDER BY company_name ASC LIMIT 50
    - `update(db, id: i64, dto: &UpdateSupplierDto) -> Result<()>`
    - `deactivate(db, id: i64) -> Result<()>` — SET is_active = 0

    **`repository/batch_repo.rs`**:
    - `insert(db, medicine_id, purchase_id, purchase_item_id, purchase_price, quantity, remaining_qty, expiry_date) -> Result<i64>` — INSERT INTO batches (...) VALUES (...) RETURNING id. This will be called inside a transaction from purchase_service, so it must accept `&Connection` (works for both standalone Connection and Transaction since Transaction implements Deref<Target=Connection>).
    - `get_current_stock(db, medicine_id: i64) -> Result<i64>` — D-23 formula:
      ```sql
      SELECT COALESCE(SUM(remaining_qty), 0) FROM batches
      WHERE medicine_id = ?1 AND expiry_date > date('now')
      ```
    - `get_expiry_report(db, min_days: Option<i64>, max_days: Option<i64>) -> Result<Vec<ExpiryReportRow>>` — Per RESEARCH.md Pattern 5:
      ```sql
      SELECT b.id, m.id, m.name, m.generic_name, b.quantity, b.remaining_qty,
             b.purchase_price, b.expiry_date,
             CAST(julianday(b.expiry_date) - julianday('now') AS INTEGER) AS days_remaining
      FROM batches b
      JOIN medicines m ON m.id = b.medicine_id
      WHERE m.is_active = 1 AND b.remaining_qty > 0
      ```
      Append optional date range filter conditions dynamically (safe parameterized approach). ORDER BY days_remaining ASC.

    **`repository/settings_repo.rs`**:
    - `get_string(db, key: &str) -> Result<Option<String>>` — SELECT value FROM settings WHERE key = ?1
    - `set_value(db, key: &str, value: &str) -> Result<()>` — INSERT OR REPLACE INTO settings (key, value) VALUES (?1, ?2)

VALUES (...) per D-22. Uses `&Connection` as param name since Transaction also works via Deref.

    **SERVICES** (each function takes `&Connection`, returns Result<T, CommandError> — converts rusqlite errors via `?`):

    ---

    **`services/medicine_service.rs`**:
    - `create_medicine(db, dto: &CreateMedicineDto) -> Result<MedicineDto, CommandError>`:
      - Validate retail_price >= purchase_price (D-16). Use `(retail_price * 100.0).round() >= (purchase_price * 100.0).round()` to avoid float comparison issues (compare as integer cents/paise).
      - Validate category is in allowed set (defense-in-depth — D-13 also has CHECK constraint)
      - Validate unit is in allowed set
      - Call medicine_repo::insert, then medicine_repo::find_by_id, return MedicineDto with current_stock=0 (new medicine has no batches yet)
    - `update_medicine(db, id: i64, dto: &UpdateMedicineDto) -> Result<MedicineDto, CommandError>`:
      - Validate retail_price >= purchase_price (if both provided)
      - Find existing medicine, verify exists
      - Call medicine_repo::update, then find_by_id
    - `deactivate_medicine(db, id: i64) -> Result<()>`:
      - Verify medicine exists
      - Call medicine_repo::deactivate
    - `list_medicines(db) -> Result<Vec<MedicineListItem>, CommandError>`:
      - Fetch all medicines via find_all
      - For each, compute current_stock via batch_repo::get_current_stock
      - Map to MedicineListItem (includes purchase_price for owner command)
    - `search_medicines(db, query: &str) -> Result<Vec<MedicineListItem>, CommandError>`:
