<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React UI rendering | UI state derived from session data received via IPC |
| Frontend routing | URL-based navigation, protected routes by role |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-13 | Information Disclosure | Sidebar nav items (frontend-only hiding) | accept | Sidebar hides Pharmacist-inaccessible nav items in UI, but the REAL enforcement is in Rust command guards (Plan 2). Frontend-only hiding is a UX courtesy, not a security boundary. Per D-07 and architecture guidance. |
| T-01-14 | Elevation of Privilege | Direct URL navigation to /users as pharmacist | accept | Frontend routes check session.role and redirect unauthorized users. Backend commands also enforce role guards — double protection. |
| T-01-15 | Information Disclosure | Login audit log viewed by unauthorized role | mitigate | `get_login_attempts` Tauri command calls `require_owner()` guard — even if a pharmacist URL-navigates to /audit, the IPC call will return FORBIDDEN. The audit page should handle this by showing error and redirecting. |
</threat_model>
