\section{Introduction}
PharmaCare is a desktop pharmacy management system for a single-branch private pharmacy. It replaces manual registers and spreadsheets with a fast, offline-first system for medicine inventory, point of sale, purchases, batch tracking, returns, debts, reports, users, audit logs, and backups.

The application stores day-to-day data locally in SQLite. Internet is not required for sales, stock intake, reports, returns, or authentication. Internet is only needed for optional Google Drive backup and email OTP password recovery.

\subsection{Core Capabilities}
\begin{itemize}
  \item Manage medicine catalog, categories, units, prices, reorder levels, shelf locations, and notes.
  \item Track stock at batch level with expiry dates, purchase prices, and remaining quantities.
  \item Process fast sales through a keyboard-friendly POS screen.
  \item Deduct stock by FIFO, using earliest-expiry stock first.
  \item Block expired, zero-stock, and over-quantity sales.
  \item Record supplier purchases and automatically create batches.
  \item Process customer returns, supplier returns, and stock write-offs.
  \item Track customer debts and record repayments.
  \item Generate owner-only reports and export them to PDF.
  \item Back up and restore the local database safely.
\end{itemize}

\section{Getting Started}
\subsection{First-Time Setup}
When the application is opened for the first time, the setup wizard creates the first Owner account.
\begin{enumerate}
  \item Enter full name.
  \item Choose a unique username.
  \item Set a password with at least 6 characters.
  \item Optionally enter an email address for password recovery.
  \item Save the setup. The first user becomes the Owner.
\end{enumerate}
\noteBox{Keep at least one active Owner account. PharmaCare blocks actions that would remove the last active Owner.}

\subsection{Login}
\begin{enumerate}
  \item Enter username and password.
  \item Press Enter or click Login.
  \item The system opens the dashboard according to your role.
\end{enumerate}
Every login attempt is recorded in the audit log. Failed login messages are intentionally generic for security.

\subsection{Password Recovery}
If SMTP settings and owner email are configured, use \textbf{Forgot Password?} on the login screen.
\begin{enumerate}
  \item Request the OTP code.
  \item Check the configured owner email.
  \item Enter the OTP.
  \item Set a new password.
\end{enumerate}

\section{Point of Sale}
The POS screen is designed for fast checkout and keyboard use.

\subsection{Sale Steps}
\begin{enumerate}
  \item Search for medicine by name.
  \item Select the required medicine from live results.
  \item Enter quantity.
  \item Optionally enter item discount.
  \item Optionally enter bill discount.
  \item Toggle tax according to the sale.
  \item Select Cash, Card, or Credit.
  \item If Credit is selected, enter customer name.
  \item Confirm the sale.
\end{enumerate}

\subsection{Business Rules}
\begin{itemize}
  \item Stock is checked before sale confirmation.
  \item Expired stock is excluded.
  \item Stock is deducted FIFO by batch.
  \item Prices are recalculated by the backend from database values.
  \item Pharmacist discounts require the cashier discount setting to be enabled.
  \item Sale records store immutable line snapshots of price, cost, discount, and tax.
\end{itemize}

\section{Suppliers and Purchases}
Suppliers store company details, contact information, payment terms, and notes. Purchases record stock received from suppliers.

\subsection{Recording a Purchase}
\begin{enumerate}
  \item Open Purchases and click Record Purchase.
  \item Select supplier.
  \item Enter invoice number, purchase date, and payment status.
  \item Add medicine line items with quantity, expiry date, and unit purchase price.
  \item Save the purchase.
\end{enumerate}
Saving a purchase creates purchase records, batch records, and positive stock movements inside one atomic transaction.

\section{Returns and Corrections}
PharmaCare supports customer returns, supplier returns, and stock write-offs.

\begin{longtable}{>{\raggedright\arraybackslash}p{3.5cm}>{\raggedright\arraybackslash}p{5cm}>{\raggedright\arraybackslash}p{5cm}}
\toprule
\textbf{Action} & \textbf{Used When} & \textbf{Stock Effect} \\
\midrule
Customer return & Customer returns sold items. & Resellable stock is restored. Damaged or expired return is logged as loss. \\
Supplier return & Owner sends purchased stock back to supplier. & Stock is deducted from selected batch. \\
Write-off & Stock is damaged, expired, or unusable. & Stock is deducted and loss is logged. \\
\bottomrule
\end{longtable}

Returns cannot exceed original sale quantities. All returns store reason, date, condition, quantity, and processing user.

\section{Debt Tracking}
Debt tracking is used for formal customer credit records.
\begin{enumerate}
  \item Create a debt with customer name, items, due date, and notes.
  \item Record partial or full payments.
  \item The system updates paid, remaining, overdue, and due-soon status.
\end{enumerate}
Debt alerts appear on the dashboard for overdue and due-soon amounts.

\section{Backup and Restore}
Backups protect the local SQLite database.
\begin{itemize}
  \item Manual backup is started from Settings.
  \item Automatic backup runs at the configured time while the app is running.
  \item Local backup can be used for USB or offline fallback.
  \item Google Drive backup uploads to the configured Drive account when internet is available.
  \item Restore requires Owner confirmation.
  \item A pre-restore backup is created before any restore operation.
\end{itemize}

\section{FAQ}
\textbf{Do I need internet?} No. Internet is optional for Google Drive backup and email OTP recovery.\\[0.5em]
\textbf{Where is data stored?} In the local SQLite database in the application data directory.\\[0.5em]
\textbf{Can pharmacists see purchase prices?} No. Purchase price and profit data are hidden and blocked by backend role checks.\\[0.5em]
\textbf{How does FIFO work?} Stock is deducted from the earliest-expiring valid batch first.\\[0.5em]
\textbf{How many backups are kept?} The system keeps recent backups according to configured retention, with the default design preserving the last 30 daily backups.
